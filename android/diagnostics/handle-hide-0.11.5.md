# Android 0.11.5 调整选文时隐藏圆环

## 问题与交互

0.11.4 使用移动或缩小方形触摸窗口的方法给选文手柄让路，导致圆环大小随选区变化。用户要求改为：移动选文手柄时隐藏圆环。

- 自动选文圆环收到来源区域的按下通知后，隐藏圆环并设置 `FLAG_NOT_TOUCHABLE`，原应用继续接收手柄拖动。复制菜单隐藏期间保持隐藏；菜单恢复后显示同一个圆环。不会把手柄操作当作圆环首次定位。
- 原生入口在初选静默期间也跟踪来源菜单，第一次调整选区时，按住手柄仍不显示圆环。松手后使用最新选文；后续调整复用窗口、当前页和首次触摸状态。
- 圆环大小按屏幕、键盘与用户设置初始化后保持固定，不再因手柄或复制工具栏而缩小。只避让选区端点与小型手柄窗口，复制工具栏作为初始位置参考，避免把整个工具栏当作手柄。
- 若完整尺寸无法避开手柄，暂时隐藏并让选文保持可操作；可用空间恢复后再次显示。屏幕与键盘本身的尺寸适配仍然保留。
- 隐藏期间不能新执行圆环动作。已由用户选择、正在等待来源恢复的动作继续遵守原来的来源与剪贴板校验，临时对话框不会取消这些请求。
- 初次点功能、首次空白定位、远处点击退出与主动操作时的 GTA 背景沿用现有规则。没有新增按钮、权限、依赖、后台轮询或触摸接管，没有注入手势代替用户选文。

原生自定义控件如果不提供可读菜单，无法准确获得松手时刻；这一分支保留已有的 250ms 选区稳定检查，并且只在原来源有效、未被对话框遮挡时恢复。不能据此声称所有 App 都能提供真实的拖动结束通知。

## 验证

- 修改前，真实拖动多行选区手柄失败，断言为 `Moving a selection handle must hide the wheel until release`。日志 `build/handle-hide-0.11.5-red-api35.txt`。
- 原生、标准菜单、无选区事件菜单三个重抓手柄场景，检查移动期间与按住暂停时隐藏、输入穿透、没有 GTA 遮罩、松手恢复、窗口复用及尺寸不变。首次定向 4 项通过，日志 `build/handle-hide-0.11.5-targeted-api35.txt`。
- 首次完整 50 项回归暴露 5 个兼容失败，随后修正：没有来源菜单的原生控件不再初始隐藏，复制工具栏不再作为手柄障碍。日志 `build/handle-hide-0.11.5-final-api35.txt`。
- 修正后定向 10 项中，9 项通过；新增加的首次拖动测试已经通过拖动隐藏检查，但最后的可见性断言错误地嵌套调用主线程切换。已修正测试线程调用。日志 `build/handle-hide-0.11.5-compat-targeted-api35.txt`。
- 隐藏期间窗口可以保留，但按钮尚不可见；测试等待条件已由“存在浮窗”改为“圆环内有实际可见按钮”。先前一轮 51 项的 4 个过早等待／点击失败见 `build/handle-hide-0.11.5-verified-api35.txt`，修正后的四项定向复验通过，见 `build/handle-hide-0.11.5-visible-targeted-api35.txt`。
- 随后一轮 51 项中有 1 项菜单初始化偶发失败，诊断显示尚未创建圆环；记录 `build/handle-hide-0.11.5-visible-api35.txt`。未据此推断新的生产代码问题：该项独立连续 8 次通过，前序七项组合连续 3 轮通过，分别见 `build/handle-hide-0.11.5-readiness-{1..8}.txt` 与 `build/handle-hide-0.11.5-sequence-{1..3}.txt`。
- Android 15 最终完整 51 项全部通过，涵盖首次拖动、三个重抓手柄路径、菜单复制、焦点恢复、首次定位、退出和尺寸稳定。日志 `build/handle-hide-0.11.5-final-visible-api35.txt`。临时失败状态诊断已删除，保留可见按钮判据与用户行为断言。
- Android 8 / API 26 报告 21 项、0 失败；19 项实际执行，旧 WebView 原生范围不可用及未安装 Via 各条件跳过一项。包括新增的固定尺寸隐藏与空间恢复测试。日志 `build/handle-hide-0.11.5-final-api26.txt`。
- 59 项 JVM 测试通过；Lint 0 错误、7 项既有警告。清理调试信息后的最终构建日志 `build/handle-hide-0.11.5-clean-build.log`。
- 已目视核对松手恢复截图 `build/handle-hide-0.11.5-native-after-api35.png`：完整圆环避开手柄，页面保持清晰；最终交付的 APK 与这些回归使用的生产 APK 字节一致。
