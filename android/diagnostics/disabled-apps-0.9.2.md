# Android 0.9.2：按应用禁用自动圆环

## 使用

**首页 → 禁用应用**，或 **触发与权限 → 禁用应用**。

按应用名称或包名搜索，勾选需要停用的 App 后保存。该来源中的原生选文、标准选文菜单、Telegram 复制自动入口都遵守禁用规则，不自动显示圆环或辅助按钮。取消只丢弃未保存的修改；搜索隐藏的勾选项仍会保存。

取消勾选后恢复全局触发方式，保留该应用原有的独立动作及排序。未修改的其他 App 继续保留 AUTO／BUTTON 等原规则。用户主动通过系统选文菜单、分享或剪贴板快捷入口打开 ActionHalo 仍可使用。

## 实现

- 复用 `AppRulesStore.Profile.trigger = OFF`，与原有“按应用设置触发和动作”及配置备份共用一份数据。旧 OFF 规则自动预选；已卸载但仍有配置的包名也可解除禁用。
- 批量更新先校验包名和合计 200 个 App 的规则上限，再进行一次偏好写入；任何校验失败均不部分保存。解除时仅改变触发模式，保留动作列表；空的全局默认配置会移除。
- 现有无障碍规则监听取消已显示圆环、辅助按钮和等待中的复制浮层。
- 修复 `ClipboardHaloActivity` 脱离无障碍浮层管理后的遗漏：自动请求创建及读取前检查来源规则；普通复制遵守自动模式，明确点击辅助按钮的请求遵守按钮模式；等待焦点或已经显示时禁用／暂停会立即关闭。自动请求缺少有效来源时拒绝，主动手动入口不受影响。
- 不新增权限、依赖、后台剪贴板监听或原生库；只保存用户指定的应用包名和设置。

## 验证

`assembleDebug`、`assembleDebugAndroidTest`、`testDebugUnitTest`、`lintDebug` 完成。54 项 JVM 测试通过；Lint 0 错误，7 项既有警告，无新增警告。

Android 8 / API 26 和 Android 15 / API 35 专用模拟器分别运行 54 项相关测试，覆盖禁用名单、设置界面、按应用规则、备份、复制焦点、单动作生效范围和设置分层。首次运行中，取消对话框的测试在系统异步关闭前过早断言；改为等待主线程空闲后，两端各复测 5 项禁用设置 UI 测试全部通过。API 26 按预期跳过需要 API 28 `clearPrimaryClip` 的旧用例。

两端另各通过 2 项真实无障碍测试：已显示圆环／标准选文辅助按钮在禁用时关闭，后续选区被拦截，解除后无需重启服务即可恢复。复测日志均为 `OK (7 tests)`。复制 Activity 的新增回归覆盖读取前禁用、按钮模式区别、等焦点时禁用、已显示时禁用／暂停，以及手动入口保留。

在 Android 8 模拟器实际从首页点击进入禁用列表，检查搜索、勾选列表、提示和取消／保存按钮；截图 `android/build/disabled-apps-0.9.2-ui-api26.png`。

构建日志：`android/build/disabled-apps-0.9.2-build.log`。首轮设备日志：`disabled-apps-0.9.2-api26.txt`、`disabled-apps-0.9.2-api35.txt`；修正测试后的界面与真实选文验证：`disabled-apps-0.9.2-live-api26.txt`、`disabled-apps-0.9.2-live-api35.txt`。
