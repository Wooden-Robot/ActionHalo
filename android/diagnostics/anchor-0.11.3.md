# Android 0.11.3 调整选文时保持圆环位置

## 问题与修复

用户反馈移动文字光标／选文手柄会重置圆环位置。原生路径收到不同范围就销毁并重建圆环；菜单路径在原应用重建复制菜单时也会重建圆环。另外，尚未操作圆环时拖动原应用的手柄，会收到外部按下事件，旧处理立即关闭圆环，后续菜单事件又将它重新打开。

- 同一包、来源窗口和文字节点内的有效范围变化，现在更新当前选文与保留的来源节点，不再替换圆环。保留窗口位置、当前页和首次触摸状态；正在等待的旧选文动作取消，执行时仍核对最新范围和文字。
- 复制菜单刷新时，核对同一来源窗口和包后只更新菜单窗口 ID。动作和关闭回调使用最新 ID，并核对圆环实例，避免旧回调操作新会话。
- 有限窗口的外部触摸交回来源处理；手柄拖动不再直接关闭圆环。选文取消、菜单消失、来源离开和授权撤销仍清理入口。进入圆环操作后的中心关闭、远处松手退出和 GTA 背景规则保持原有行为。
- 没有新增按钮、触发倒计时、依赖或权限；没有增加后台剪贴板读取。

- 修改前，真实选文手柄拖动也会替换菜单圆环窗口（38 → 40）。仅复用菜单仍不能避免外部触摸关闭；修复该处理后，真实手柄、连续范围变化、首次定位和最终准确复制的 3 项回归通过。日志：`build/anchor-0.11.3-handles-api35.txt`。
- Android 8 / API 26 完整选文套件报告 20 项、0 失败；18 项实际执行，旧 WebView 原生范围不可用及未安装 Via 各跳过一项。包含新增的原地更新、位置保持和取消测试。日志：`build/anchor-0.11.3-final-api26.txt`。
- 59 项 JVM 测试通过；Lint 0 错误、7 项既有警告。日志：`build/anchor-0.11.3-final-build.log`。
