# Android 0.9.1：动作的生效 App

## 使用

入口：操作管理 → 动作右侧「⋮」→ 生效 App。

- 全部 App：默认行为，升级后原有动作不受影响。
- 仅指定 App：仅在所勾选来源 App 的圆环中显示此动作。
- 排除指定 App：在所勾选来源 App 中隐藏此动作。

支持按应用名称 / 包名搜索、多选；取消不保存。非“全部”模式至少选择一个 App，每个动作最多指定 200 个 App。列表查询可启动的已安装 App，并保留已保存但当前手机不可用的包名。

这是对**选文来源**的限制；动作执行时打开哪个应用仍在“打开方式”设置。它和“先选 App，再设置动作组合 / 顺序”共存：先取该 App 的动作组合，再按生效范围过滤，保留其顺序。

## 实现和边界

- `ActionStore` 保存模式及包名，未配置时为全部；`AppRulesStore.actionsFor` 统一用于选文、菜单复制和手动入口的动作过滤。
- `ActionExecutor` 执行前再次读取当前规则，已打开圆环中的旧动作也不能绕过后续范围变更。
- 仅使用现有可信来源信息。来源不明时，“仅指定 App”动作隐藏；“排除指定 App”不会猜测来源。外部传入的 referrer 或内部来源 extra 不能伪造 `HaloActivity` 的调用方。
- Android 包名按精确值匹配。这里只保存用户选择的包名，不保存选文、剪贴板或使用历史，不增加权限、依赖或原生库。
- 动作快照包含 `appScopes`，因此备份、删除撤销、恢复默认和撤销恢复都保持一致。导入前校验所有字段、动作引用、模式、包名、数量和重复项；任何无效部分均不写入配置。
- 新版可导入 0.9.0 快照，缺少 `appScopes` 时恢复为全部。0.9.0 的严格解析器会拒绝包含新字段的备份，请用新版恢复。
- PC 的 `PluginFilter.apps / excludeApps` 提供逐动作来源规则；其不匹配项在当前 PC 圆环置灰。Android 本轮采用隐藏不匹配项以减少手机圆环占位，未修改 PC。

## 验证

构建 `assembleDebug`、`assembleDebugAndroidTest`、`testDebugUnitTest`、`lintDebug` 全部完成。54 项 JVM 测试通过；Lint 0 错误、7 项既有警告。

| 设备 | 结果 |
| --- | --- |
| Android 8 / API 26 专用模拟器 | 51 项通过，包含 9 项规则 / 持久化 / 执行复查测试、5 项实际设置及圆环 UI 测试，以及备份、动作、搜索回归 |
| Android 15 / API 35 专用模拟器 | 70 项通过，另覆盖拖拽排序、删除撤销和剪贴板入口 |

新增测试包括：默认 / 仅指定 / 排除 / 未知来源、准确包名匹配、独立动作组合不能绕过、执行前复查、保存与取消、空选校验、搜索不丢勾选、重建页面恢复、真实分享圆环忽略伪造来源、旧快照兼容、删除撤销和非法备份拒绝后全部配置保持原样。

日志：`android/build/app-scope-0.9.1-build.log`、`app-scope-0.9.1-api26.txt`、`app-scope-0.9.1-api35.txt`。

另在 Android 8 中从实际动作「⋮」菜单进入设置，检查了三种模式及多选列表、搜索框、取消和保存按钮的可见布局；截图为 `android/build/app-scope-0.9.1-ui-api26.png`。
